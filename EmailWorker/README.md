# EmailWorker

Отдельный процесс читает непрочитанные письма из IMAP INBOX. При запуске он проверяет всю папку, затем ждёт изменений через IMAP IDLE; если сервер не поддерживает IDLE, проверяет почту каждые 30 секунд. Успешно обработанное письмо помечается прочитанным. От повторной обработки защищает запись `InboundEmails` с уникальной парой UIDVALIDITY/UID; запускайте только один экземпляр воркера на почтовый ящик.

Перед запуском скопируйте `appsettings.example.json` в `appsettings.json` и укажите `ConnectionStrings:DefaultConnection`, `ImapSettings` и `Minio`. Настройки `FileUpload` должны совпадать с API: вложения проходят те же ограничения по размеру и типу, затем сохраняются в бакет `attachments` и привязываются к публичному сообщению. Пароль почты храните в локальном конфиге или переменной окружения `ImapSettings__Password`; локальный `appsettings.json` исключён из Git. Сначала запустите API, чтобы применить миграции и создать бакет.

```powershell
dotnet run --project EmailWorker/EmailWorker.csproj
```

Неподдерживаемые, пустые и слишком большие вложения пропускаются; их имена указываются в сообщении заявки и в логе. Остальное письмо сохраняется и помечается прочитанным. Служебные письма системы, помеченные специальным заголовком, пропускаются. Ответы отправителей без доступа к заявке помечаются прочитанными и флажком для ручной проверки. При ошибке сохранения письма или загрузки допустимого вложения письмо остаётся непрочитанным для повторной попытки.

Hangfire используется только для передачи уведомления о новой заявке или сообщении в процесс API, который отправляет его через SignalR. IMAP-чтение, загрузку вложений и запись заявки выполняет сам EmailWorker через `InboundEmailService`.

Для ответов оператора по заявкам типа `Email` настройте `SmtpSettings` в API и держите API запущенным: его Hangfire-сервер отправляет письмо с текстом публичного ответа и вложениями из MinIO. Отложенное напоминание о непрочитанном изменении статуса для таких заявок не планируется. Адрес SMTP-отправителя должен соответствовать ящику, который читает EmailWorker, чтобы ответы клиента попадали в нужную переписку.

После первого письма клиент получает подтверждение с номером заявки. Ответ на исходное письмо или на подтверждение добавляется в ту же заявку; если она ожидала данных, проверки или была закрыта, ответ возвращает её в работу. Если заявка объединена с другой, ответ по старому почтовому треду направляется в родительскую заявку. Отдельная смена статуса почтовой заявки отправляется клиенту сразу.

Новому отправителю создаются Employee и User с ролью `User` и `IsActivated=false`. Активировать такую учётную запись может Operator или SuperAdmin; до активации вход и восстановление пароля недоступны. Заявка от клиента с одним учреждением автоматически связывается с ним; если учреждений несколько, заявка создаётся без учреждения.

Сервис обработки входящих писем находится в `Application/Services/InboundEmailService.cs`; `MailWorker` отвечает за подключение, IMAP IDLE, поиск непрочитанных писем и отметку `Seen`. Входящие ответы создают публичное сообщение, а не внутренний комментарий.
